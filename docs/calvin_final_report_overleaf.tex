\section{项目概述}

本项目基于 StarVLA 框架，在 CALVIN ABC$\rightarrow$D 长程机器人操控基准上实现并评测一个 Action Policy Model。
CALVIN ABC$\rightarrow$D 要求模型在训练环境 A/B/C 上学习机器人操作策略，并在未见过的环境 D 中连续完成 5 个子任务链，因此该任务重点考察模型的跨环境泛化能力、长程链式执行能力以及对误差累积的鲁棒性。

本项目采用 Vision-Language-Action（VLA）路线，选择 \BaseModel{} + \ActionHead{} 作为基础模型架构，并在公开数据预训练、CALVIN ABC 监督微调的基础上，引入 Failure-Aware Post-Training 策略，对评测过程中暴露出的低成功率任务和典型失败模式进行针对性优化。

整体训练与评测流程如下：

\begin{lstlisting}[caption={整体训练与评测闭环}]
Public / LIBERO Pretraining
        ↓
CALVIN ABC Supervised Finetuning
        ↓
CALVIN D Evaluation
        ↓
Failure Pattern Mining
        ↓
Failure-Aware Post-Training
        ↓
CALVIN D Re-evaluation
\end{lstlisting}

本项目的核心目标不是仅提升单步动作预测精度，而是提升模型在 CALVIN ABC$\rightarrow$D 长程任务链中的平均链长和 Task 1--Task 5 阶段成功率，尤其关注模型在未见环境 D 中的稳定执行能力。

\section{模型与技术路线选择}

\subsection{技术路线选择}

本项目选择 VLA 路线，而不是 World Model（WM）路线。
VLA 模型直接从视觉观察、语言指令和机器人状态中预测低层连续动作，具有训练流程直接、推理开销较低、与 StarVLA 现有 CALVIN 工具链兼容性较好的优点。

在 StarVLA 支持的动作头中，PI / LayerwiseFM 使用 Flow-Matching 扩散式动作头，一次预测一个 action chunk。
相比单步动作预测，该方式可以建模短期轨迹结构，有利于机器人在连续控制中保持动作平滑性和局部时序一致性。
因此，本项目选择该类动作头作为主要策略模型。

\subsection{选择 VLA 路线的原因}

\textbf{数据效率。}
VLA 路线可以直接利用已有的机器人轨迹数据进行监督学习，训练目标清晰，工程实现成本较低。
对于两天实训任务而言，VLA 路线更适合快速完成从数据准备、监督微调、评测到失败分析的完整闭环。
相比之下，WM 路线通常需要额外学习环境状态转移或视频生成模型，对数据规模、训练稳定性和算力要求更高。
在有限时间内，完整训练或充分调优一个 World Model 的风险较大。

\textbf{泛化能力。}
CALVIN ABC$\rightarrow$D 需要模型从训练环境 A/B/C 泛化到未见过的 D 环境。
VLA 模型依赖大规模视觉-语言模型作为表征骨干，可以继承预训练模型中的视觉语义理解能力，对背景、光照、物体外观变化具有一定鲁棒性。
本项目进一步通过公开数据预训练和 CALVIN ABC 监督微调，使模型同时具备通用视觉语言表征和目标任务相关的低层动作能力。

\textbf{长程规划能力。}
VLA 路线本身并不显式建模完整长程世界状态，因此在长任务链中容易出现误差累积。
为缓解这一问题，本项目没有简单增加训练步数，而是引入评测驱动的 Failure-Aware Post-Training：先在完整 CALVIN D 评测中挖掘失败模式，再对高频失败任务进行重采样和加权训练，从而使训练目标更贴近长程评测中的真实问题。

\textbf{计算成本与推理效率。}
VLA 策略在推理时直接输出动作，不需要显式进行未来视频生成或多步世界状态预测，因此推理成本相对较低，更适合 CALVIN 长程 rollout 评测。
在本项目的硬件条件下，VLA 路线能够在较短时间内完成多轮训练与评测迭代。

\subsection{与 WM 路线的对比}

World Model 路线的优势在于能够显式建模未来状态变化，理论上更适合长程规划、遮挡场景推理和反事实预测。
对于需要复杂物理交互或长期状态预测的任务，WM 可能具备更强的可解释性和规划潜力。

但在本项目中，WM 路线存在以下限制：

\begin{enumerate}
  \item 训练成本更高，需要学习视觉状态转移或未来视频生成。
  \item 对数据规模和数据质量要求更高。
  \item 推理阶段可能需要额外的 rollout、采样或规划过程，计算开销更大。
  \item 两天实训时间内完整验证 WM 路线的风险较高。
\end{enumerate}

因此，本项目选择 VLA 作为主路线，并将主要创新点放在长程失败模式挖掘和 Failure-Aware Post-Training 上，以更低工程风险完成可复现的实验闭环。

  \item 环境 D 中物体颜色、位置或视觉分布变化导致动作泛化不足。
\end{enumerate}

\section{Failure Pattern 分析}

\subsection{Failure logging 设计}

为分析模型在 CALVIN D 环境中的失败模式，本项目在评测脚本中加入 failure logging 机制。
每当模型在某条任务链中首次失败时，系统会记录该失败案例的细粒度信息，并保存为 \code{failure_log.jsonl}。

每条 failure log 包含以下字段：

\begin{lstlisting}[caption={failure log 字段}]
{
  "sequence_i": "评测序列编号",
  "subtask_i": "失败子任务在任务链中的位置",
  "stage": "失败阶段，对应 Task 1~Task 5",
  "subtask": "失败子任务名称",
  "eval_sequence": "完整任务链",
  "lang_annotation": "失败任务对应语言指令",
  "steps": "rollout 执行步数",
  "reason": "失败原因",
  "gif_path": "debug 模式下失败视频路径"
}
\end{lstlisting}

此外，评测脚本会生成 \code{failure_summary.json}，统计平均链长、各阶段成功率、不同阶段失败次数和不同子任务失败次数。

\subsection{失败模式分类}

根据 CALVIN D 评测结果，本项目将主要失败模式分为四类。

\subsubsection{链式误差累积}

模型在 Task 1 或 Task 2 中通常能够完成任务，但随着任务链推进，前序动作中的轻微误差会改变后续任务的初始状态，使模型逐渐偏离训练分布。
该问题在 Task 3--Task 5 中更加明显。

典型表现包括：

\begin{enumerate}
  \item 前一个任务完成位置不够精确，导致后续物体位置偏移。
  \item 机器人末端执行器停留在不利姿态，影响下一任务起始动作。
  \item 多个小误差在长程 rollout 中逐步累积，最终导致 oracle 条件无法触发。
\end{enumerate}

对应改进方案包括：

\begin{enumerate}
  \item 使用 action chunk time weighting，提高后半段动作的 loss 权重。
  \item 通过 failure-aware sampling 增加长链后段高频失败任务的训练占比。
  \item 对 Task 3--Task 5 的失败案例进行单独统计，分析是否存在阶段性退化。
\end{enumerate}

\subsubsection{动作精度不足}

部分失败案例中，模型能够大致移动到目标附近，但末端执行器位置、姿态或位移幅度不够准确，导致任务 oracle 条件无法触发。
该问题在 block pushing、slider、drawer 等任务中较为明显。

典型表现包括接近目标但没有触发成功判定、推动物体距离不足、末端执行器与物体接触点偏移、动作方向正确但幅度不足或过大。
对应改进方案包括在 action loss 中提高关键动作维度权重、对低成功率任务进行 task-aware oversampling，并使用 per-task success rate 定位动作原语级别的短板。

\subsubsection{夹爪时机错误}

抓取、释放、拉动等任务对 gripper 开合时机非常敏感。
如果 gripper 过早闭合、过晚释放或方向预测错误，会导致任务失败。
该问题可能影响 lift、place、drawer 等任务。

典型表现包括抓取物体前 gripper 已提前闭合、释放位置正确但 gripper 没有及时打开、拉动 drawer 时接触不稳定、gripper 输出在连续动作中发生抖动。
对应改进方案包括在通用 failure-aware post-training 中提高 gripper 维度 loss 权重、保持较短训练步数以避免破坏已有基础操作能力，并对涉及 gripper 的任务单独统计失败率。

\subsubsection{环境 D 泛化失败}

CALVIN ABC$\rightarrow$D 的训练环境为 A/B/C，评测环境为 D。
环境 D 中的背景、光照、物体布局和视觉分布可能与训练环境存在差异，导致视觉表征和动作预测出现偏移。

典型表现包括模型识别目标物体不稳定、对颜色或物体位置变化敏感、在训练环境中成功率较高但迁移到 D 环境后下降明显。
对应改进方案包括引入视觉增强策略，例如颜色扰动、亮度扰动、随机裁剪等；采用更多跨环境公开数据进行预训练；冻结视觉语言 backbone，仅针对 action head 做轻量后训练，降低过拟合风险。

\section{Failure-Aware Post-Training 方法}

\subsection{方法动机}

标准监督微调通常基于训练集中的离线轨迹进行行为克隆，优化的是平均动作预测误差。
但 CALVIN ABC$\rightarrow$D 的难点在于长程闭环执行：模型在 Task 1 中产生的小误差会改变 Task 2 的初始状态，后续任务进一步偏离训练分布，最终导致链式成功率下降。

因此，仅依赖标准监督微调可能不足以优化 Task 3--Task 5 的长程执行表现。
本项目采用评测驱动的后训练流程：

\begin{lstlisting}[caption={评测驱动后训练流程}]
Evaluate -> Mine Failures -> Reweight Data/Loss -> Post-train -> Re-evaluate
\end{lstlisting}

该方法将 CALVIN 评测中真实暴露的失败案例转化为训练信号，以较低工程成本提升模型在长程任务中的稳定性。

\subsection{Failure-Aware Sampling}

评测阶段产生的 \code{failure_log.jsonl} 包含失败子任务对应的语言指令。
后训练时，dataloader 会读取该日志，统计出现频率最高的失败指令，并提高这些 hard instructions 在训练 batch 中的相对占比。

具体实现上，本项目没有直接复制失败样本，也没有改变数据格式，而是对非失败指令样本进行轻量降采样，使失败指令在训练过程中更频繁出现。
该设计能够避免过度复制少量失败样本导致过拟合，同时让模型在后训练阶段更集中地修正常见失败任务。

\subsection{Weighted Action Loss}

CALVIN 动作维度为：

\begin{lstlisting}[caption={CALVIN action dimension}]
[x, y, z, roll, pitch, yaw, gripper]
\end{lstlisting}

在长程操控中，平移动作和夹爪控制通常比旋转噪声更直接影响任务成功。
因此，本项目在 Flow-Matching action head 的 velocity prediction loss 中加入动作维度权重。

通用 failure-aware 设置为：

\begin{lstlisting}[caption={通用动作维度权重}]
[x, y, z, roll, pitch, yaw, gripper]
[1.0, 1.0, 1.0, 0.7, 0.7, 0.7, 1.5]
\end{lstlisting}

该设置强调末端位置控制和 gripper 开合时机，同时降低旋转维度噪声对整体 loss 的影响。
对于 open drawer、close drawer、lift object、move slider 等任务，gripper 开合方向和时间点对成功率影响明显，因此该加权策略有助于提升动作执行稳定性。

\subsection{Action Chunk Time Weighting}

PI / LayerwiseFM 动作头一次预测一个 action chunk。
长程闭环执行中，chunk 后半段动作对后续状态转移有直接影响。
如果后半段动作偏差较大，模型在下一次 replan 时会面对更偏离训练分布的状态。

因此，本项目在动作 chunk 的时间维度上加入线性权重，使后段动作的 loss 略高于前段动作。

\begin{lstlisting}[caption={动作 chunk 时间权重}]
early-step weight: 1.0
late-step weight: 1.25
\end{lstlisting}

这鼓励模型不仅预测当前动作，还要使整个短期轨迹更加平滑和可执行，从而缓解连续任务中的误差累积。

\section{Push-Aware 改进方案}

\subsection{问题发现}

根据 per-task success rate 分析，当前模型最低成功率任务集中在 \code{push_{color}_block_left/right} 一类横向推动任务中。
例如：

\begin{lstlisting}[caption={低成功率 push 任务}]
push_blue_block_right: 19.4%
push_red_block_left: 24.4%
push_pink_block_left: 26.5%
push_red_block_right: 36.4%
push_pink_block_right: 41.2%
push_blue_block_left: 59.0%
\end{lstlisting}

这说明模型在 free block lateral pushing 中存在明显短板。
该类任务与 \code{push_into_drawer} 不同，后者成功率仍达到 84.4\%，说明模型不是完全不会执行 push，而是在没有轨道约束的横向推动中难以稳定控制接触和方向。

\subsection{Push 任务失败根因分析}

\code{push_{color}_block_left/right} 的低成功率可能来自以下原因：

\begin{enumerate}
  \item 接触点不稳定：末端执行器没有准确接触 block 的合适位置。
  \item 水平位移预测不足：x/y 方向动作幅度不够或方向错误。
  \item 持续接触能力不足：模型在 action chunk 后半段无法保持稳定推动。
  \item 颜色与方向组合泛化不足：例如 \code{push_blue_block_right} 明显低于其他 push 任务。
  \item 长程状态偏移：前序任务造成 block 或机械臂状态变化，使后续 push 更难完成。
\end{enumerate}

\subsection{Push-Aware Sampling}

仅依赖 failure log 中的 top-k 指令可能低估 push 的真实难度。
原因是 CALVIN 评测记录的是任务链中的首次失败，如果模型在 Task 2 已经失败，则后续 push 任务可能根本没有被执行到。

因此，本项目进一步引入 Push-Aware Sampling：除 failure log 中高频失败指令外，将 push-block left/right 这类低成功率任务显式加入 hard instruction set，并提高其采样频率。

目标 hard tasks 包括：

\begin{lstlisting}[caption={Push-Aware hard tasks}]
push_red_block_left
push_red_block_right
push_blue_block_left
push_blue_block_right
push_pink_block_left
push_pink_block_right
\end{lstlisting}

该策略能够更直接地针对当前模型最明显的动作原语短板进行修复。

\subsection{Push-Focused Weighted Loss}

通用 failure-aware loss 强调 gripper 维度，但对于 free block pushing，主矛盾不是 gripper 开合，而是水平位移方向、幅度和持续接触。
因此，本项目设计 push-focused action loss：

\begin{lstlisting}[caption={Push-focused action loss weights}]
[x, y, z, roll, pitch, yaw, gripper]
[1.6, 1.6, 0.8, 0.5, 0.5, 0.5, 0.7]
\end{lstlisting}

该权重设计的含义如下：

\begin{enumerate}
  \item 提高 x/y 权重，强化水平推动方向和幅度。
  \item 降低 z 权重，避免模型学习过多竖直动作。
  \item 降低 roll/pitch/yaw 权重，减少旋转噪声对 loss 的干扰。
  \item 降低 gripper 权重，使模型在 push 中更关注持续推动而不是开合动作。
\end{enumerate}

\section{局限性与未来改进}

本项目采用的 Failure-Aware Post-Training 具有稳定、低成本、可解释的优点，但也存在一定局限。

首先，该方法仍然主要依赖离线监督数据，不能像在线 RL post-training 那样直接优化真实 rollout reward。
因此，如果模型失败来自训练数据中完全没有覆盖的状态，单纯重采样和加权 loss 的提升可能有限。

其次，当前 failure-aware sampling 主要以语言指令作为 hard case 标识，无法完全区分同一指令下不同初始状态导致的失败。
例如，同样是 \code{push_blue_block_right}，不同 block 初始位置、机械臂姿态和前序任务状态可能导致不同失败原因。

第三，如果失败主要来自环境 D 中的视觉分布变化，仅通过 action head 后训练可能无法完全解决问题。
未来可以进一步引入视觉增强、颜色扰动、域随机化或更强的跨环境数据预训练。

后续改进方向包括：

\begin{enumerate}
  \item 引入 push-specific data augmentation，例如 left/right 对称增强。
  \item 对 failure log 记录更细粒度的状态信息，例如失败时物体位置和机械臂末端位置。
  \item 按任务类别设计不同 action loss 权重，而不是全局统一权重。
  \item 探索 replan\_steps 对 push 和长程链式成功率的影响。
  \item 引入轻量在线 RL 或 DAgger 式数据收集，进一步优化真实 rollout 表现。
\end{enumerate}

\section{结论}

本项目基于 StarVLA 框架，在 CALVIN ABC$\rightarrow$D 长程操控基准上实现并评测了一个 VLA Action Policy Model。
通过公开数据预训练、CALVIN ABC 监督微调和 Failure-Aware Post-Training，本项目完成了从训练、评测、失败挖掘到针对性改进的完整实验闭环。

实验分析表明，模型在长程任务链中主要受到误差累积、动作精度不足、夹爪时机错误和环境 D 泛化失败等因素影响。
其中，per-task success rate 显示 \code{push_{color}_block_left/right} 是当前最明显的低成功率任务簇，说明模型在 free block lateral pushing 中存在动作原语级别短板。

针对上述问题，本项目提出并实现了 Failure-Aware Post-Training，包括 failure-aware sampling、weighted action loss 和 action chunk time weighting。
同时，针对 push 类任务进一步设计 Push-Aware Post-Training，通过提高 push hard instructions 的采样频率和强化 x/y 平移 loss，尝试提升模型在横向推动任务中的稳定性。

总体而言，该方法能够将 CALVIN 评测结果转化为可操作的训练信号，在较低工程风险和计算成本下，对模型长程链式执行能力进行针对性优化。
